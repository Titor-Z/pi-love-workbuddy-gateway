# pi-love-workbuddy-gateway

![banner](/docs/banner.png)

**把 WorkBuddy（腾讯 CodeBuddy 国内版）的订阅额度，接给 pi 用。**

你订阅了 WorkBuddy，里面有额度、还有些限时免费的好模型。但它的桌面端太重了，
你只想在 pi 里用那些额度。这个小程序就干这一件事：在本机开一个接口，
让 pi 像用任何模型一样用 WorkBuddy 的模型。

一个文件，双击就能跑，不吃内存，不用装 Python，不用装 Node。

## 它解决什么问题

- **你不想开 WorkBuddy 桌面端。** 它只在你**第一次登录**时需要。登录完，令牌由本程序自己续期。
- **你想在 pi 里直接选那些模型。** 装好后 `pi` 的模型列表里会多出 31 个 WorkBuddy 模型。
- **你想一眼看出哪些免费。** 模型名后面直接标着费用，比如
  `Step-5-Preview · 免费 · 独家限免 · 至2026-10-25`。

## 快速开始

### 第一步：确认你已经在 WorkBuddy 桌面端登录过

只要你在这台电脑上装过并登录过 WorkBuddy，就够了。之后可以不再打开它。

> 程序需要一个小钥匙（登录态文件是加密的）来读你的登录信息。第一次运行它会自动
> 去 WorkBuddy 里取一次，之后就记在自己手里了。

### 第二步：跑起来

```bash
./pi-love-workbuddy-gateway
```

看到这几行就成功了：

```
登录态：/Users/你/Library/Application Support/CodeBuddyExtension/Data/Public/auth/workbuddy-desktop.info
密钥指纹：9127dea1b44020a7
对外    https://192.168.1.5:8788
pi 连   http://127.0.0.1:8788/v1
控制台  http://127.0.0.1:8789/
```

> 「对外」那一行就是**其他电脑要填的地址**。本机 pi 用的是同一个端口号，
> 只是走 loopback。详见[一个端口号，两种绑定](#一个端口号两种绑定)。

### 第三步：生成 pi 的配置

打开控制台 `http://127.0.0.1:8789/`，进「模型」页，点**下载 models.json**，
或者点**复制**再把内容粘进 `~/.pi/agent/models.json`。

### 第四步：在 pi 里用

打开 pi，输入 `/model`，会看到 `workbuddy` 这一组，选一个就行。

也可以直接指定：

```bash
pi --model workbuddy/step-5-preview "帮我看看这个项目"
```

## 常用命令

只有两个子命令、两个参数。**多余的参数会直接报错并打印用法**，不会静默忽略。

| 命令 | 作用 |
|---|---|
| `pi-love-workbuddy-gateway` | 网关模式（默认）。这台机器持有凭证，其他电脑连它 |
| `pi-love-workbuddy-gateway gateway -d -addr 0.0.0.0:8788` | 同上，写全 |
| `pi-love-workbuddy-gateway client -d -addr 192.168.1.5:8788` | 客户端模式。转发给网关 |
| `pi-love-workbuddy-gateway -help` | 用法 |
| `pi-love-workbuddy-gateway -version` | 打印版本号 |

| 参数 | 说明 |
|---|---|
| `-addr` | 网关模式：对外服务地址，默认 `0.0.0.0:8788`<br>客户端模式：要连的网关地址 |
| `-d` | 后台运行（默认开）；`-d=false` 前台打印日志 |

### 后台运行

```bash
$ pi-love-workbuddy-gateway
已转入后台，PID 59583
日志：/Users/你/.config/piloveworkbuddy/gateway.log
停止：kill 59583
```

**这是默认行为。** 命令立刻返回，网关在后台继续干活，关掉终端、断开 SSH 都不影响它。

想在终端里盯着日志就用 `-d=false`：

```bash
pi-love-workbuddy-gateway -d=false
```

停止：

```bash
kill 59583            # PID 就是上面打印的那个
# 或者
pkill -f pi-love-workbuddy-gateway
```

如果启动失败（最常见的是端口 `8788` 已被另一个实例占着），
命令会**直接把失败报出来**，而不是假装启动成功了：

```
启动失败：后台进程启动后立即退出（exit status 1）。常见原因是端口已被占用；
详情见日志：/Users/你/.config/piloveworkbuddy/gateway.log
```

### 查看余额

打开控制台总览页，右上角就是资源包余额与明细。

> **账单结算有 1～3 分钟延迟，而且是按批到账的。**
> 刚发完请求就来查很可能看到「没扣」。这不是漏计。

## Web 控制台

浏览器打开 **http://127.0.0.1:8789/** ，命令行能做的事都能在这里点。

> **v0.3.0 起控制台搬到了独立端口 `8789`。** 以前它和 API 共用 `8788`。
> 如果你升级后打开 `http://127.0.0.1:8788/` 找不到面板——那是正常的，
> 访问 `http://127.0.0.1:8789/` 即可。pi 的配置**不用改**，它连的还是 `8788`。
> 分开的原因见下一节。

| 页面 | 里面有什么 |
|---|---|
| 概览 | 今日请求数、消耗、余额、拦截/拒答；**有模型被限流时提示预计恢复时间**；14 天消费柱状图（按模型堆叠）；模型用量排行（含输入/输出/缓存命中） |
| 模型 | 实时目录，带免费／倍率／活动标记；**一键复制或下载 pi 的配置** |
| 设置 | 直接编辑 `promotions.json`，保存后立即生效，不用重启 |
| 日志 | 两个视图：**时间线**（表格，全部事件，说明列可换行）与**请求明细**（一行一次请求：模型、输入、**缓存命中**、输出、消耗、耗时）。**点任意一行会从右侧滑出抽屉**，展开这次请求的完整流水账——发了什么、回了什么、花了多少、用了多久、哪个模型、拦没拦 |
| 状态 | 版本、运行时长、进程号、各个文件的实际路径、登录态是否还有效 |
| 页脚 | 停止 / 重启网关 |

### 安全边界，先说清楚

控制台**只绑本机**，外网访问不到。它没有登录口令，靠两个机制挡住攻击：

1. **页内一次性随机数**：每次启动生成，写进返回给你的 HTML 里。接口要求请求带上它。
   别的网站虽然能向 `127.0.0.1:8789` 发请求，但**读不到我们的页面**（同源策略），
   所以拿不到这个随机数。
2. **来源校验**：写操作要求 `Origin` 与当前地址一致，遮挡伪造请求。

**这道防线挡不住什么**：能读你本机文件的程序（另一个恶意软件）依然可以绕过。
那种情况下你机器上的任何工具都不安全，需要的是系统级隔离，不是这个网关的责任。

如果你要把它**暴露到局域网或公网**（例如反向代理），必须在代理那一层加认证，
并且明白你在把 WorkBuddy 的会话凭据交给别人用。默认配置不支持也不鼓励这么做。

### 控制台在哪个端口（v0.3.0 起变了）

| 端口 | 默认 | 干什么 | 谁能访问 |
|---|---|---|---|
| **API** | `127.0.0.1:8788` | `/v1/*` 与 `/health` | pi；改 `-addr` 后可以给别人 |
| **控制台** | `127.0.0.1:8789` | 面板页面与 `/api/*` | 只绑本机 |

**为什么分开**：控制台里有余额、请求日志（**含被拦对话的正文**）、模型目录，
还有**停止 / 重启网关**按钮。以前它和 API 共用一个端口，于是改 `-addr 0.0.0.0`
直连局域网时，**控制台会跟着一起被开放出去**。分开之后，把 API 暴露到局域网
不再牵连控制台。

打开 `http://127.0.0.1:8788/` 会看到一段文字告诉你控制台在哪，不会是空白 404。

**两个端口的鉴权是独立的两套**（v0.4.0 起还有第三个端口，届时同样独立）：

- 本机 pi 走的 loopback 明文口**不设密钥**：能访问它的程序本来就能直接读配置目录
  里的登录态，再加一道密钥挡不住任何东西。
- 控制台靠「页内一次性随机数 + 来源校验」保护，防的是**跨站脚本**
  （别的网站偷偷向 `127.0.0.1` 发请求）。
- **这两道防线防不住网络访问**：控制台若被改成 `0.0.0.0`，局域网里另一台设备
  正常打开就能看到全部内容、也能按停止/重启。启动日志会对此打出警告。
  远程访问必须在反向代理那一层加认证。

### 设计系统

界面遵循仓库里的 [`design.md`](design.md) —— 一套叫 **Gauge** 的设计系统。
它从公开的 RawBlock 演化而来，但已经不是它：RawBlock 为**海报**而生，Gauge 为**仪表**而生。
那份文档写明了继承了什么、改了什么、否决了什么（含理由），改之前值得先读一遍。

两套配色、四级边框刻度（5/3/2/1px）、两套字号刻度（展示/密集）、三个动效场景。
顶栏是玻璃（`backdrop-filter`）—— 本界面里唯一符合「背后有东西在动」这个条件的地方。

### 暗色模式

设置页顶部可以切 **亮色 / 暗色 / 跟随系统**，偏好存在浏览器本机，不上传。

它不是把亮色反过来那么简单。直接反转得到的是纯白配纯黑（对比度 21:1）——
那是印刷品的对比，屏幕上的大面积亮白会发光、发糊，看久了眼睛累。所以：

- **底色抬离纯黑**（`#141416`），用抬高的灰来表达「层」：下层是页面、上层是卡片；
- **文字不用纯白**（`#e4e4e7`），仍然 14:1，远超可读性要求，但不刺眼；
- **粗边框单独一档色**（`#6b6b72`）。黑色在白底上是「收」的，白色在黑底上是「放」的，
  同样的 5px 白线会比黑线厚重得多。

换主题时颜色会淡过去而不是硬切（你要是开了系统的「减少动态效果」就不淡）。
如果你开了系统的「增强对比度」，上面这些让步会让位：边框提回正文色。

其它：原生滚动条与输入框的明暗也跟着主题走；首次加载前就把主题定下来了，不会先闪一下白底。

### 停止与重启

控制台页脚有按钮，效果与下面的命令一致：

```bash
kill $(pgrep -f pi-love-workbuddy-gateway)   # 停止
pi-love-workbuddy-gateway                    # 重启
```

**重启会让进程号变化**：做法是退出前把新的自己派生出来，
而不是用 `exec` 原地替换（后者在 Windows 上不可用）。
配置、日志、事件文件都是接着用的，不影响 pi 那边已经配好的地址。

## 配置文件与日志

都放在 `~/.config/piloveworkbuddy/` 下面。目录不存在会在首次启动时自动创建。

```
~/.config/piloveworkbuddy/
├─ promotions.json   ← 促销活动（免费到哪天）
├─ gateway.log       ← 给人看的文本日志
└─ gateway.jsonl     ← 给 Web 面板统计的结构化事件
```

两个文件职责不同：`gateway.log` 是给人 `tail` 的，`gateway.jsonl` 是给面板读的。
后者是 JSONL（一行一个 JSON），有专门的 `msg` 字段所以直接 `tail` 也不难读：

```json
{"t":"2026-10-14T05:07:44+08:00","kind":"chat","msg":"◀ glm-5.3 | 5.6s | 流式完成 | credit=1.34",
 "model":"glm-5.3","credit":1.34,"in":8328,"out":13,"ms":5648,"status":200,"stream":true}
```

被后端内容审核拦下，事件是：

```
{"t":"2026-10-14T05:07:44+08:00","kind":"chat","msg":"◀ glm-5.3 | 2.1s | 流式完成 | credit=0.12 | ⚠️命中内容审核(policy)",
 "model":"glm-5.3","credit":0.12,"in":120,"out":30,"status":200,"stream":true,
 "blocked":true,"blocked_reason":"policy","upstream":{"http":403,"code":11128,"msg":"安全策略拦截"}}
```

**判据分两栏，请分开理解**（完整契约见源码 `internal/blocked` 包注释）：

- **确定拦截 `blocked`**：后端亲口承认拦了——流式通道的 `finish_reason=content_filter`
  / 非空 `refusal`，或硬阻断通道的策略码（如非 200 的 `11128`）。这部分是准的。
- **疑似拒答 `refused`**：模型礼貌说「抱歉我不能……」时，后端给的也是 `finish_reason=stop`，
  和正常回复没有结构区别，协议层**无法**可靠识别。这一栏是本工具的**文本启发式猜测**
  （`internal/blocked` 里的拒答短语表），可能误报也可能漏报，**不计入拦截率**。

两栏分开，是因为「猜的」绝不能当「确定」用。日后想加新的策略码或拒答说法，
**只改 `internal/blocked` 一个模块**，其余代码不用动。

### 流水账：点开一行看完整对话

被拦或疑似拒答的那次，除了上面那些统计字段，还会多两个正文字段：

```
"request":"[{\"role\":\"user\",\"content\":\"教我绕过审核\"}]"
"response":"抱歉，我不能提供这个内容"
```

这就是「pi 和 WorkBuddy 之间到底做了什么」的真相——面板「日志」页**点任意一行**，
抽屉会分层展示：概览（时间/模型/方式/状态/耗时/花费）、判定（是否拦截及原因/是否疑似拒答）、
请求（消息数/是否带工具/最大输出/正文）、响应（结束原因/调用工具/token/正文）、上游错误。

**边界**：只有被拦/拒答的事件才留正文，**正常对话一律不存**——这是「能看清黑盒」与
「隐私」之间取的平衡。正文是明文、落在本机文件里，因此另有 **30 天保留期**：
超过 30 天的正文在面板里会被脱敏（统计数字照旧保留）。

**不引入数据库**：日志用的是 JSONL 而不是 SQLite，这是刻意的——引数据库要么带来
第三方依赖、要么要 cgo，会破掉「单二进制、零依赖」这个前提。单用户量级下全量扫描是毫秒级，
足够支撑这个抽屉。

### `gateway.log`

每次启动与每次请求都会记一行，末尾追加，不会覆盖历史：

```
[2026-10-14 04:21:31] 版本：v0.1.1
[2026-10-14 04:21:31] 登录态：/Users/你/Library/.../workbuddy-desktop.info
[2026-10-14 04:21:31] 密钥指纹：9127dea1b44020a7
[2026-10-14 04:21:41] ▶ hy3 | stream=true
[2026-10-14 04:21:44] ◀ hy3 | 2.555s | 流式完成
```

日志里**不会出现任何令牌**。如果某次回复被后端的内容审核拦了，会额外记一条：

```
[2026-10-14 04:21:44] ⚠️ 命中内容审核 | hy3
```

前提同上：只有 `finish_reason=content_filter` 或非空 `refusal` 才会触发。
如果只是「模型礼貌地说了它不能做某件事」，那是正常回复，不算拦截。

启动时加 `-log ""` 可以关掉落盘，只写屏幕。

桌面端改写登录态后（它自己刷新了令牌），会多出一行：

```
[2026-10-14 05:12:33] 检测到登录态文件变化，已重新载入
```

这条是正常的，说明网关已经跟上桌面端的新令牌。
如果 401 之后自动重试成功了，你会先看到 `⚠️` 相关的一行再看到正常完成的请求。

### `promotions.json`

**为什么需要它：** WorkBuddy 的接口只告诉你「这个模型现在免费」，**不告诉你免费到哪天**。
那个日期只写在它的桌面端界面上。所以我们自己记一份。

格式：

```json
{
  "hy3": {
    "free_until": "2026-10-31",
    "note": "每日赠送免费额度（7月6日-10月31日）"
  }
}
```

- 键是模型 ID（用 `models` 命令看到的那个）。
- `free_until` 会显示成「至2026-10-31」。
- `note` 只是给人看的备注，不显示在模型名里。
- **这个文件不存在也完全没问题**，只是不显示截止日期。

参考 `promotions.example.json`。

## 遇到问题

**提示找不到登录态文件**
WorkBuddy 桌面端没登录过。打开它登一次即可。

**返回 401**
WorkBuddy 那边的登录过期了。打开桌面端重新登录一次。

   v0.2.1 起这一种大多能自愈：网关检测到 401 会自动重读登录态再试一次，
   日志里会看到 `检测到登录态文件变化，已重新载入`。只有重读后令牌没变
   （说明真的失效）才会失败，那时请重新登录。

**回复很慢**
换个快点的模型试试，比如 `deepseek-v4-flash`。

**回复被拦了，说内容不合适**
这是 WorkBuddy 后端的内容审核。它有时候不是因为你问的问题敏感，而是 pi 自己的
提示词里有安全术语（`exploit`、`sandbox`、`credential` 这类）被误判。

**真被拦**时后端会亲口给信号：要么流式通道里 `finish_reason=content_filter` 或非空
`refusal`，要么直接回一个非 200 + `{"code":11128,"msg":"安全策略拦截"}` 这样的
错误体。这两种情况网关都会记一条 `⚠️命中内容审核(<原因>)`，面板「日志」页的
「只看确定拦截」能筛出来。换个说法或者换个模型通常能过去。

**模型只是礼貌拒绝**（「抱歉，我不能……」）后端给的是 `finish_reason=stop`，和正常
回复没有结构区别——协议层无法可靠识别。此时面板会标「疑似拒答」，这是本工具的
**文本启发式猜测**，可能误报也可能漏报，**不计入拦截率**，不要把它当成真被拦。

想知道**到底发了什么才出问题**：去「日志」页点那一行，抽屉里能看到完整的请求正文和
回复正文。**凡是失败的请求都留**（被拦、被限流、模型不存在、网络中断、聚合失败），
只有**成功的正常对话不存**。正文保留 30 天后自动脱敏。

**我是不是「体验用户」，限流是不是因为这个**
可以从「余额」页直接看出来。我们实测过本机的资源包明细，主包叫
**`CodeBuddy个人体验版`**（500 额度，已用掉约 36），另有几个「个人版拉新权益包」
和「国内运营裂变包」。所以**确实是个人体验版的额度**。

不过这**不能直接推出「限流是因为体验版」**——后端从未在任何字段里说明限流的
判定依据，我们也没有任何官方说明（见下）。只能确定地表述为：
「你在用个人体验版额度，且该模型有独立的频率上限」。

**请求被限流 / 频率超了**
WorkBuddy 对**单个模型**有用量与频率限制，命中时后端返回 HTTP `429` + 业务码
`6004`，文案形如：「您的使用量已超出频率限制，将在 2026-10-14 23:13:09 UTC+8 重置，
您也可以切换其他模型继续使用。」

实测口径（来自本机日志的 8 次真实记录，**非官方文档**）：

| 观察到的 | 值 |
|---|---|
| 业务码 | `6004` |
| 生效范围 | **按单个模型**（撞墙时同账号其他模型仍正常） |
| 窗口 | 滚动式，实测约 **3 小时**（20:13 撞墙 → 23:13 重置） |
| 性质 | 可自愈、可绕开，非封号 |

**这不是内容拦截**，面板上会标「限流」而不是「拦截」，也不计入拦截率。
**概览页**会直接提示「有模型正在频率限制中」及预计恢复时间；点日志里那一行，
抽屉里还能看到是哪个模型、发了什么。

> ⚠️ **官方没有公开的限制说明。** 我们查过 workbuddy.cn 全站（sitemap 仅 11 个页面，
> 无帮助中心、无 API 文档，`/terms` 路由 404），定价页只讲套餐档位与促销，
> 没有一个字提到频率上限。上表是实测观察，可能随账号类型、时段、模型而变化，
> **不构成官方口径**。要准确数字请以 WorkBuddy 客户端内显示或官方客服答复为准。

**和 WorkBuddy 桌面端同时用**
可以，网关每次请求前都会重读登录态文件，桌面端刷新令牌后下一次请求就会跟上。
偶发的 401 会自动重试一次。但不建议两边同时高强度请求。

**想确认它在干活**
浏览器打开 <http://127.0.0.1:8788/health>，会看到账号和令牌状态。
（面板在 <http://127.0.0.1:8789/>，注意端口不同。）

## 多台电脑、笔记本外出怎么用

这一节回答一个很实际的问题：**出差、换机器、家里和公司各一台，怎么用？**

好消息：**每台机器装一次 WorkBuddy 登录后就可以卸载，网关之后再也不需要它。**
登录态一旦拿到，令牌由网关自己续期。整件事的客户端依赖只有「每台机器一次」。

### 方案一：每台机器各装一次，然后卸载（推荐）

每台机器上装 WorkBuddy、登录、跑一次网关让它提取解密密钥，然后**卸载客户端**。
之后这台机器就能独立运行网关，**同一账号可以在多台机器上用**。

### 方案二：把密钥和登录态搬到另一台机器（可省掉重复安装）

登录态文件是加密的，解密密钥（`atRestSecretKey`）**不在文件里**，而是从 WorkBuddy
客户端里提取的、绑定在那台装过客户端的机器上。所以：

1. 在装过 WorkBuddy 的机器上取出 `atRestSecretKey`，设进环境变量
   `WORKBUDDY_AT_REST_SECRET`；
2. 把加密的登录态文件（`workbuddy-desktop.info`）也复制过去；
3. 另一台机器用 `-auth-file` 指向它，**全程不需要装 WorkBuddy**。

> ⚠️ 这等于把 WorkBuddy 的凭据多复制了一份到另一台设备。笔记本丢了，那两份东西
> 就都泄露了，等同账号在别人手里。用之前想清楚这个风险。

### 多台机器用同一个账号：官方支持，网关有信息盲区

先把两件事分开，它们的确定性完全不同：

**① 官方客户端之间，同账号多设备同时用 —— 官方是支持的。**
两台 WorkBuddy 登录同一个账号、同时正常对话，这是常规用法。后端在设计上就容忍
同一账号存在多份有效的登录态。

**② 网关跨机器时，看不见别的机器的令牌更新 —— 这是真实的信息盲区。**
WorkBuddy 的刷新令牌会轮换（这一点已实测确认）。网关和桌面端在**同一台机器**上，
靠「每次请求前重读文件 + 401 时强制重读再试一次」能自动跟上（v0.2.1 起）。
但**两台机器各有一份文件、互相看不见对方的轮换**，所以网关比官方客户端多了一个
风险：别的机器刷新过之后，网关手里那枚可能已经旧了。

**这个风险的实际表现是「偶发掉线」，不是「必然互踢」。** 网关遇到 401 会自动重读
并重试一次，多数情况能自愈。真正需要注意的是：**如果两台机器长期同时高强度使用，
偶发重新登录是可以预期的**——这不代表账号有问题。

**建议**：正常用即可，不需要刻意只开一台。如果真的频繁掉线，间隔几分钟重试，或者
给第二台机器换一个账号，能彻底避开这个盲区。

### 三个端口各自防住了什么

| 端口 | 绑定 | 防护 |
|---|---|---|
| `127.0.0.1:8788` | 只绑 loopback | **不需要密钥**。能访问它的程序本来就能直接读配置目录里的登录态，再加一道挡不住任何东西 |
| `<局域网IP>:8788` | 只绑局域网网卡 | **网关密钥 + TLS + 证书指纹**。不带密钥一律 401 |
| `127.0.0.1:8789` | 只绑 loopback | 页内一次性随机数 + 来源校验，防跨站脚本 |

三点必须清楚：

- **控制台永远是本机的**。它没有开关，也不会因为 `-addr` 改成 `0.0.0.0`
  而跟着暴露——它是独立端口、独立绑定，代码里没有把它绑到别处的路径。
  即便如此，「页内随机数 + 来源校验」防的是**跨站脚本**，
  **不是**网络访问；万一哪天有人把这行代码改了，这两道防线对局域网访问完全无效。
- **`0.0.0.0` 是「每块局域网网卡各绑一个」，不是「绑所有地址」**。
  loopback 是特意留给本机 pi 的，所以别指望用 `0.0.0.0:8788` 去访问。
- **不要把网关直接放到公网上。** 这个 TLS 是给可信局域网用的，
  密钥在客户端机器上是明文存储的。

### 方案三：一台网关 + 多台客户端（v0.4.0 起，在家共享推荐）

前面两个方案的本质是「每台机器各自持有一份凭证」。它们的问题是：
**WorkBuddy 的刷新令牌会轮换，两份凭证互不相让，同时用会互相踢。**

v0.4.0 起有第三条路，把凭证收回单一持有者：

```
   网关机器（装过一次 WorkBuddy）
        │  只有它持有凭证、只有它刷新令牌
        │  relay 端口 https://<IP>:8790
   ┌────┴────┬─────────┐
 笔记本     台式机     平板
 -mode client -mode client ...
 本机不持有凭证
```

**做法**：只有一台机器需要装一次 WorkBuddy、跑网关；其他机器**什么都不用装**，
以客户端模式连过来。全网只有网关一个 refreshToken，所以多设备同时请求
**不会互相把对方踢下线**。

> **⚠️ 这一版只解决「在家共享」。**
> 客户端本机不持有凭证，**断开局域网就完全不能用**——外出时还是得用方案一或方案二。
> 「凭证冷同步到客户端、外出自动切网关」在后续版本。

**开启步骤**：

1. 在网关机器上直接启动（什么都不用加）。它默认就是网关模式，
   转发服务自动开放，控制台在 <http://127.0.0.1:8789/>。
2. 在另一台机器上以客户端模式启动：
   ```bash
   ./pi-love-workbuddy-gateway client -d -addr 192.168.1.5:8788
   ```
3. 打开那台机器的控制台 <http://127.0.0.1:8789/>，在「多设备」页：
   - 填入网关地址与**网关密钥**（在网关控制台「多设备」页能看到）
   - 点「连接」，网页会取出网关证书的指纹
   - 把它与网关控制台显示的指纹**逐位比对**，一致才点「确认」
   - 保存后自动重启生效

   密钥与指纹都在网页上填，**不走命令行**——命令行参数会留在 shell history
   和 `ps` 输出里，而这串字符等于账号访问权。
4. 那台机器上的 pi 照旧指向 `http://127.0.0.1:8788/v1`——**客户端自己也是一个
   完整网关**，只是把请求转交给真正的网关。**pi 的配置两种模式都不用改。**

### 一个端口号，两种绑定

| 地址 | 明文/TLS | 谁用 |
|---|---|---|
| `127.0.0.1:8788` | 明文 HTTP | 本机的 pi。**所有机器都一样，pi 配置不用改** |
| `<局域网IP>:8788` | TLS + 网关密钥 | 其他电脑的客户端 |
| `127.0.0.1:8789` | — | 控制台，只绑本机 |

同一个端口号绑在不同网卡上不冲突。这样其他电脑只需要记「网关机器的 IP」，
不用记第二个端口号。

本机 pi 走的那个 loopback 明文口**不设密钥**：能访问它的程序本来就能直接读配置
目录里的登录态，再加一道密钥挡不住任何东西。

**「停用设备」不是封禁。** 设备名是客户端自己报的，持有密钥的人换一个名字就能
重连，所以**做不到只踢一台**。真要让人连不上只能重置网关密钥，代价是所有设备
都要重新填入。控制台「多设备」页把这一点写在了按钮旁边。

### 方案三 + 凭证冷同步（v0.5.0 起，外出也能用）

上面那条只能在家用——客户端本机没有凭证。v0.5.0 把凭证也同步过来：

1. 网关控制台「多设备」页**开启「凭证同步」**（独立开关，默认关）。
   它和「开放转发服务」是两件事：转发是把请求送进来，同步是把账号令牌交出去，
   风险高一个量级，所以要分开想、分开开。
2. 客户端照常连上。之后它每 30 分钟自动拉一份凭证，用**本机自己的密钥**加密
   存在 `~/.config/piloveworkbuddy/credentials.json`。磁盘上不留明文。
3. 出门前在客户端控制台「多设备」页点「立即同步」，或者它每 30 分钟自己同步一次。
4. 到地方之后，在客户端控制台「多设备」页点「切换到网关模式」。
   它会做四项检查（本地有副本、能解密、令牌非空、未过期），
   缺哪一项就说哪一项。
5. 停掉本进程，然后**不带 `-mode client`** 重新启动：
   ```bash
   ./pi-love-workbuddy-gateway
   ```
   从此这台机器自己刷新令牌，与「装过一次 WorkBuddy 的机器」走的是同一条代码路径。

**三条硬规则**（违反了多设备共享就会退回互相踢）：

- **单向**：网关 → 客户端。客户端**绝不刷新、绝不回写、绝不推送**。
  真要带回外出期间的刷新，手动拷 `credentials.json` 比开推送通道好——
  推送是一个能改网关持有凭证的写入口。
- **版本号（epoch）单调递增**：网关每同步一次 +1，客户端拒收更旧的。
- **不自动覆盖**：客户端切过网关模式后它的 epoch 更高，回连时**网关拒绝覆盖**，
  面板提示「本机凭证比网关新」，用哪一份由你决定。不会静默丢东西。

**⚠️ 外出切网关前必须停掉客户端那个进程。** 从那一刻起两台机器都在刷新同一个
账号的令牌，而刷新令牌会轮换——同时热就会互相踢。这是整套方案唯一不能自动化的
地方：网关不知道客户端已经切走了。

**凭证同步失败的退避**：1 → 2 → 4 → 8 → 16 → 30 分钟，成功一次立刻回到 30 分钟。
不会无限重试，也不会因为一次失败就停止。

## 安全说明

- 本机的 pi 口与控制台口都只绑 `127.0.0.1`，外部网络访问不到。
  对外那个口是 TLS + 网关密钥，不带密钥一律 401。
- **你的令牌不会被打印、不会被上传。** 程序只在本机读写那份登录态文件。
- 令牌过期时它**会自动帮你续期**，并把新令牌写回原文件——这样 WorkBuddy 桌面端
  下次打开还是登录状态。
- **它也会跟着桌面端走。** 桌面端自己刷新令牌时，网关会在下一次请求前发现文件变了，
  换成新令牌；真的撞上 401 时会自动重读再试一次。不会和桌面端抢着刷新。
- 唯一的例外：自动续期会调用 WorkBuddy 的官方接口，这是它本来就会做的事。
- **客户端模式下，本机不持有令牌。** 凭证由网关同步过来、加密存在本机，
  只在切到网关模式时才被使用。同步方向是单向的：客户端不会刷新、不会回写、
  也不会推送凭证给网关。

### 两类测试

**单元测试**挑出风险最高的地方逐个钉死。密码学代码不用「自己加密、自己解密」自我证明，
而是**固定密钥与 nonce，把 Python 参考实现产生的密文写死在测试里**，Go 实现必须能解开：

```go
const (
	referenceKeyID    = "c9534a8b5bbb49fe"        // 钉住密钥派生
	referenceAADHex   = "57422d41414400010000..." // 钉死 AAD 字节布局
	referenceEnvelope = `{"$wbEncrypted":1,...`    // 参考实现产生的密文
)
```

密钥派生、AAD 框、GCM 参数任何一处漂移，测试立刻红。这是整个项目最不能出错的地方 ——
一旦漂移，你机器上所有已存在的加密登录态都会解密失败。

**集成测试**用一个假的 WorkBuddy 后端把整条请求路径跑通，覆盖单测碰不到的部分：
鉴权头是否真的发出去了、SSE 是否真的逐字节透传、后端错误是否被正确翻译、
令牌过期时是否真的去续期并把新令牌加密写回文件。

- **零第三方依赖（Go 侧）。** 只用 Go 标准库，`go.mod` 里没有 require。
- 代码分模块：`config` / `atrest` / `credential` / `upstream` / `catalog` / `gateway` / `journal` / `billing` / `panel` / `logging` / `wbapi`。
- 开发约定、架构决策、踩过的坑都记在 `AGENTS.md`（**不提交到仓库**）。

### Web 控制台

前端源码在 `web/`，栈是 **Vite + Svelte 5 + Chart.js**，不引 CSS 框架。

```bash
cd web
npm install
npm run build     # 输出到 ../internal/webui/dist
npm run dev       # 可选：热更新，需要网关已经在跑
```

**构建产物（`internal/webui/dist/`）是入库的**，就是为了让你 clone 下来直接 `go build`
就能出带界面的二进制，不需要 Node。所以**改了前端一定要重新 build 并提交** `dist`。

`internal/webui/dist` 而不是 `web/dist`，是因为 `go:embed` 不能引用上级目录；
嵌入的资源必须由拥有它的那个包自己声明。

字体（Archivo Black / Work Sans / Space Mono 的 latin 子集，共 79 KB）也是自托管的，
嵌入二进制。**项目承诺不向任何第三方回传数据，所以不能用字体 CDN** ——
那会把这句话变成假话。三个字体都没有中文字形，中文走系统回退；嵌 CJK 要 5～15 MB，不值得。

### 它只连通这几个后端接口

| 用途 | 接口 |
|---|---|
| 对话补全 | `POST /v2/chat/completions` |
| 令牌续期 | `POST /v2/plugin/auth/token/refresh` |
| 模型目录 | `GET /console/enterprises/personal/models` |
| 资源包余额 | `POST /v2/billing/meter/get-user-resource` |

前三个走 `copilot.tencent.com`，余额走 `www.codebuddy.cn` —— 两个不同的域名，
仅看代码很容易找错地方。

对话接口返回的本来就是标准 OpenAI SSE，所以网关是**字节透传**，不做协议翻译。
唯一的感觉不到的工作是：补鉴权头、把 pi 的 `developer` 角色改成后端认的 `system`、
非流式请求时把 SSE 聚合成一个 JSON。

401 时例外：那时会重读一次登录态再重发。读到的令牌不同才发，相同就报错。

```
internal/credential/   登录态定位、解密、刷新、401 重读
internal/upstream/      后端客户端（对话 + 模型目录，401 重试在这里）
```
